# INBOX

Drop anything you learned that these documents don't say. **A rough entry beats none.** The next refresher verifies it (or marks it *unverified*), merges it into its home with credit, then removes it here.

## Where entries end up

| Type | Home |
|---|---|
| Best practice | 03 (code) or 14 (workflow) |
| Methodology | 10, 11, or 14 |
| Design choice | 01, as a decision record |
| Change rule | 04, as a lockstep set |
| Failure story | 06 |
| Debugging tip | 05 |
| Limitation | 15 |
| Dependency note | 13 |
| Principle | 16, once proven |

## Template

```markdown
### <summary>
- **Type / Author / Date:**
- **What:**
- **Why:** what improves, or what breaks without it.
- **Evidence:** files, commits, PRs, or the incident.
```
